# 0007. 指摘の重さは満たした軸の数で決め、外部の人の文面が届くだけのときは起動できる人の軸を半分に数える

- ステータス: 承認
- 日付: 2026-11-08

## 文脈

- ADR 0001 は、設定が 1 つだけなら使い方しだいで、3 つの軸が重なると 2026 年の事件と同じ形になるとした。ADR 0006 は、どの規則がどの軸を満たすかを決めた
- SARIF の結果の重さ(level)は、`none`、`note`、`warning`、`error` の 4 つ
- claude-code-action と codex-action は、既定で起動できる人を書き込み権限のある人に絞る。ただし絞っているのは起動した人で、エージェントが読む文面の書き手ではない。メンテナーが外部の人の issue で `@claude` と呼べば、その issue の本文はエージェントに届く。claude-code-action には、届けるコメントの書き手を絞る `include_comments_by_actor` がある

## 検討した選択肢

重さ

1. 満たした軸の数で決める。3 つで `error`、2 つで `warning`、1 つ以下は出さない
2. 1 と同じで、1 つだけのときは `note` で出す
3. 規則ごとに固定する

外部の人の文面が届くだけのとき

1. 起動できる人の軸を半分に数える
2. 満たしたと数える
3. 数えない(起動した人だけを見る)

## 決定

高橋さんが、重さは 1、文面は 1 を選んだ。

- エージェントを動かすステップごとに、軸ごとの値を足す
  - 起動できる人: 起動の制限を外した(ADR 0006)なら 1。外部の人が起こせるトリガーで動くが、起動の制限があるなら 0.5。それ以外は 0
  - 許した道具: 広い道具か、PR の head の checkout があれば 1
  - 権限と秘密情報: 期限の無いトークン、他の秘密情報、書き込みの権限、未指定の権限のどれかがあれば 1
- 合計が 3 なら `error`、2 以上 3 未満なら `warning`、2 未満なら出さない。`note` は使わない
- 指摘は当たった規則ごとに出し、重さはそのステップの合計で決める。指摘の文には、満たした軸と、その理由になった設定を書く

| 起動できる人 | 許した道具 | 権限と秘密情報 | 合計 | 重さ |
|---|---|---|---|---|
| 1 | 1 | 1 | 3 | `error` |
| 0.5 | 1 | 1 | 2.5 | `warning` |
| 1 | 1 | 0 | 2 | `warning` |
| 0 | 1 | 1 | 2 | `warning` |
| 0.5 | 1 | 0 | 1.5 | 出さない |
| 1 | 0 | 0 | 1 | 出さない |

## 理由

- ADR 0001 の考えをそのまま重さにでき、1 行の設定だけでは騒がない
- 外部の人の文面が届くだけのときを半分に数えると、メンテナーが外部の issue でエージェントを呼ぶ実際の経路を `warning` として拾いつつ、起動の制限そのものを外した設定(`error` になりうる)と区別できる

## 受け入れたトレードオフ

- 1 つの軸だけの危ない設定(claude-code-action の `show_full_output: true` など)は出ない
- 外部の人が起こせるトリガーが無いワークフローでも、許した道具と権限と秘密情報がそろえば `warning` になる。予定で動いて外部の issue を読むワークフロー(ADR 0006 で見分けられないとしたもの)を拾える一方、内部だけで使うワークフローでは誤検知になる
- 0.5 は概算で、外部の文面が実際にエージェントに届くか(プロンプトがその文面を含むか、`include_comments_by_actor` で絞っているか)までは見ていない

## 再検討する条件

- 公開リポジトリに当てて、`warning` が多すぎて使われないとき、または `error` になるべき事例が `warning` にとどまるとき
- 利用者から、1 つの軸だけの設定も見たいと求められたとき(`note` を足す)
