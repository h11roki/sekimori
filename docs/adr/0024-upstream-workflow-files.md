# 0024. workflow_run の上流は、同じ検査に渡されたワークフローから名前で探し、そのトリガーで起こせる人を決める

- ステータス: 承認
- 日付: 2026-11-13

## 文脈

- ADR 0022 は、workflow_run の上流を、下流の `if:` に書かれた上流のイベントの比較だけで読み、上流のファイルは探さないとした。ADR 0009 の作りが、1 つのファイルずつ検査するため
- 調査(docs/survey/2026-11.md)では、`error` から選んだ 15 件のうち 2 件、全体から選んだ 30 件のうち 2 件が、上流のワークフローが `push: tags` だけで動くのに、下流の `if:` では絞っていない形の誤検知だった
- 高橋さんに、残る誤検知のうちどれを直すかを聞き、「上流のファイルを読む」が選ばれた(2026-11-13)
- GitHub の文書(workflow syntax、2026-11-13 に確かめた)
  - `on.workflow_run.workflows` は、上流のワークフローの名前と比べる。`*`、`?`、`+`、`!` などの glob の形も使える
  - `name:` を省いたワークフローは、画面に置き場所のパスで出るが、`workflows` でそのパスを指せるとは書かれていない
  - 別のリポジトリのワークフローを指せるかは、読んだ範囲には書かれていなかった
- CLI と Action は、ふつう `.github/workflows` を丸ごと渡すので、上流のファイルも同じ実行に含まれる

## 検討した選択肢

1. 検査に渡されたワークフローを全て読んでから、`name:` の表を作り、下流の `workflows` の名前を完全一致で探す。上流のトリガーから起こせる人を決め、ADR 0022 の `if:` による判定と合わせて、狭い方を取る
2. 1 と同じで、glob の形も展開して探す
3. 下流のファイルと同じディレクトリを、渡されなくても自分で読みに行く

## 決定

高橋さんが「上流のファイルを読む」を選び、読み方は Claude が 1 を選んだ(2026-11-12 に「承認取らなくていい」)。

- CLI は、渡されたファイルを全て読んでから検査する。読めないファイルは、これまでどおりエラーに出し、表には入れない
- ライブラリは、読めたワークフローから `name:` と起こせる人の表(`Upstreams`)を作り、`assess` に渡す
- 上流のトリガーから、起こせる人を ADR 0022 と同じ 3 つの段に分ける
  - 書き込める人:`workflow_dispatch`、`schedule`、`repository_dispatch`、`release` だけ
  - 絞っている:それらと `push`、`create`、`delete`、`merge_group` だけ。Dependabot の枝や、外部の人が書いた PR の文面が入りうるため
  - 誰でも:それ以外のイベントを 1 つでも含む(`pull_request`、`issues`、`workflow_run`、`workflow_call` など)
- 下流の `workflows` の名前ごとに、表から完全一致で探す。glob の形を含む名前と、見つからない名前は「誰でも」とする。名前が複数あれば、最も広い段を取る
- ADR 0022 の下流の `if:` による段と、上流のファイルによる段のうち、狭い方を、そのステップの上流の段とする。どちらも上流のイベントを狭めるもので、両方が成り立つため
- `name:` は文字の大小を区別して比べる

## 理由

- 1 つのファイルずつの作りのままでは、上流のトリガーで決まる誤検知を消せない
- 名前の完全一致に限れば、表に無い名前を誤って「書き込める人」と読むことはない。glob を展開すると、別のリポジトリや渡されなかったファイルの上流を見落としたまま狭める恐れがある(選択肢 2)
- 渡されていないファイルを読みに行くと、利用者が検査の対象を選べなくなり、ファイル 1 つだけを検査したときの結果も変わる(選択肢 3)

## 受け入れたトレードオフ

- 検査に渡したファイルの組によって、同じワークフローの結果が変わる。ファイル 1 つだけを渡すと、上流は見つからず「誰でも」になる
- CLI は全てのファイルを読んでから検査するので、平文でも、最初の指摘が出るまで全てを読む時間がかかる
- glob の形の `workflows` と、`name:` の無い上流と、別のリポジトリの上流は、これまでどおり「誰でも」とする
- 上流の `branches` などの絞り込みや、上流のジョブの `if:` は読まない
- 上流がさらに workflow_run で動くときは、たどらずに「誰でも」とする

## 再検討する条件

- glob の形の `workflows` が多く使われていると分かったとき
- 上流が別のリポジトリにある形が多く見つかったとき
