# 0020. 利用者向けの使い方は、リポジトリの根の README に英語で書き、設計の理由は ADR に任せる

- ステータス: 承認
- 日付: 2026-11-13

## 文脈

- v0.1.0 を出し、Action として使えるようになった(ADR 0017)。使い方の例は ADR 0019 の中にしか無く、リポジトリには README が無い
- GitHub は、リポジトリの根の README をリポジトリの最初の画面に出す。Marketplace に載せるときも、README を説明に使う
- 個人プロジェクト共通の CLAUDE.md は、文章を日本語で書くと決めている。一方で ADR 0010 は、使う人が世界にいるので、CLI の出力を英語にした
- 高橋さんに README を作ってよいかを聞き、「続けて」と返ってきた(2026-11-13)

## 検討した選択肢

1. README を英語で書く。使い方(Action と CLI)、規則、重さ、出力、確かめ方、制限を書き、設計の理由は ADR(日本語)へのリンクにする
2. README を日本語で書く
3. README を英語と日本語の 2 つ置く

## 決定

高橋さんが判断を任せ(2026-11-12 に「承認取らなくていい」)、Claude が 1 を選んだ。

- リポジトリの根に `README.md` を英語で置く
- 載せるのは、何を検査するか、Action の使い方、CLI の入れ方と使い方、規則の一覧、重さの決め方、出力と終了コード、リリースの確かめ方、制限、ライセンス
- 規則の説明は、CLI と SARIF が出す文(`Rule::description`)と同じ中身にする
- 使い方の例の SHA は、v0.1.0 で実際に使える値を書く
- 設計の理由は書かず、`docs/adr/` へのリンクにする。ADR は日本語のまま
- CLAUDE.md の「文章は日本語」の、README だけの例外とする

## 理由

- 使う人が世界にいるので、最初の画面が英語でないと使い方が伝わらない。CLI の出力を英語にした ADR 0010 と同じ理由
- 2 つの言語で置くと、一人で両方を同じに保つ手間がかかる(選択肢 3)
- 理由まで README に書くと ADR と二重になり、片方だけが古くなる

## 受け入れたトレードオフ

- 日本語の利用者には、README が読みにくい
- 設計の理由を知りたい英語の利用者には、ADR が読めない
- 規則や入力を変えるたびに、README も直す必要がある

## 再検討する条件

- 日本語の README を求められたとき
- Marketplace に載せるときに、README の形を変える必要が出たとき
