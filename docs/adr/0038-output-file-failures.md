# 0038. SARIF のファイルは一時ファイルに書いてから名前を変え、書けなかったことは `--format github` で注釈にする

- ステータス: 承認
- 日付: 2026-11-15

## 文脈

- ADR 0037 で、次の 2 つをトレードオフとして受け入れた
  - 書いている途中で失敗した SARIF のファイルが残る。Action はファイルがあれば `sarif-file` を出すので、送るステップが JSON の誤りで落ち、本当の原因が隠れる
  - `--sarif-file` や `--summary-file` を書けなかったことは標準エラー出力にだけ出て、`--format github` でも注釈にならない。Action の画面には「終了コード 2」しか出ない
- 読めないワークフローは、`--format github` では注釈にしている(ADR 0035)

## 検討した選択肢

1. SARIF は同じディレクトリの一時ファイルに書き、書き終えてから名前を変える。失敗したら一時ファイルを消す。ファイルが書けなかったことは、`--format github` では `::error` の注釈にする
2. 失敗したら SARIF のファイルを消すだけにする
3. 今のまま

## 決定

高橋さんが判断を任せ(2026-11-15 に「止まらないで。開発改善を進めて」)、Claude が 1 を選んだ。

- 一時ファイルの名前は、SARIF のファイルの名前に `.partial` を足したもの
- 書けなかったことの注釈は `file` を付けない(ワークフローのファイルの指摘ではないため)。注釈を標準出力に書けなければ、標準エラー出力に出す

## 理由

- 名前の変更は同じファイルシステムの中なら一度に起きるので、書きかけの SARIF は元の名前で見えない。前の実行の SARIF も、書き終えるまで残る(選択肢 2 では、消す前に落ちると残る)
- 注釈にすれば、Action の画面で、何が書けなかったかが分かる

## 受け入れたトレードオフ

- 一時ファイルを消せなかったときは `.partial` のファイルが残る。そのときは消せなかったことも出す
