# 0037. CLI は `--sarif-file` と `--summary-file` で SARIF とジョブの要約もファイルに書き、Action は sekimori を 1 回だけ動かす

- ステータス: 承認
- 日付: 2026-11-15

## 文脈

- Action は sekimori を 3 回動かす(注釈、要約のための平文、SARIF)。ADR 0035 で、検査は速いので時間の差は小さいとして受け入れた
- PR #52 のレビューで、要約の整形(`\r` の処理、字下げ、1 MiB の上限に合わせて切る)を shell で書いたために、3 回とも重大か中の指摘が出た。YAML が壊れる、`bash -e` で SARIF が出ない、ちょうど改行で切れると最後の行を消す、など。shell の部分は Rust のテストで確かめられない
- 3 回の実行の終了コードを shell で合わせる必要があり、平文の実行の終了コードは見ていない

## 検討した選択肢

1. CLI に `--sarif-file <PATH>` と `--summary-file <PATH>` を足す。標準出力は `--format` のまま出し、SARIF はファイルに書き、要約は Markdown にしてファイルの末尾に足す。Action は `--format github --sarif-file ... --summary-file "$GITHUB_STEP_SUMMARY"` で 1 回だけ動かす
2. `--format summary` を足して Markdown を出す。Action は 3 回のまま
3. 今のまま

## 決定

高橋さんが判断を任せ(2026-11-15 に「止まらないで。開発改善を進めて」)、Claude が 1 を選んだ。

- 要約は、`## sekimori` の見出しの下に、平文の出力(読めないファイル、抑える指示の警告、指摘)を 4 字の字下げで書く。`\r` は改行にする。ファイルに前からある分と合わせて 1,000,000 バイト(GitHub の上限は 1 MiB)を超えるなら、超える行の手前で切り、切ったことを書く。見出しと切ったことの文も入らないなら書かない。書くことが無ければファイルに触れない
- SARIF のファイルは `--format sarif` の標準出力と同じ中身
- `--sarif-file` と `--summary-file` の値が空なら、そのファイルを書かない。`--summary-file "$GITHUB_STEP_SUMMARY"` を、要約の無い runner や手元でも使えるようにするため
- ファイルに前から中身があれば、要約の前に空行を置く。前の中身が改行で終わっていなくても見出しになるようにするため
- ファイルを書けなければ、ファイルの名前とエラーを標準エラー出力に出して終了コードを 2 にする。SARIF のファイルが書けなくても、要約は書く
- Action の `exit-code` はこの 1 回の終了コードになる(ADR 0036)
- Action はリリースのバイナリを使うので、Action の切り替えはこの引数を持つ版を出したあとに入れる
- Action は SARIF のファイルがあるときだけ `sarif-file` を出す。書けなかったときに、無いファイルを送るステップが動かないようにするため

## 理由

- 整形が Rust の 1 か所に集まり、切り方や `\r` の扱いを単体テストで確かめられる
- 検査は 1 回になり、注釈と要約と SARIF が同じ結果から作られる
- 終了コードを shell で合わせる必要が無くなる

## 受け入れたトレードオフ

- 要約が書けないときも終了コードが 2 になる。PR #52 では、要約が書けなくても `exit-code` には sekimori の結果を出し、注釈で警告していた。今は、頼まれた出力を書けないことを失敗として扱う
- CLI の引数が 2 つ増える
- 書いている途中で失敗した SARIF のファイルは残るので、`sarif-file` が出て送るステップが JSON の誤りで落ちることがある(ディスクが一杯のときなど)
- ファイルが書けなかったことは、`--format github` でも注釈にならず、ログの標準エラー出力にだけ出る
- 1 回の実行なので、標準出力に書けなかったり sekimori が落ちたりすると、SARIF と要約も書かれない。3 回動かしていたときは、SARIF の実行は注釈の実行と別だった
- 標準出力に書けなければ、その時点で止まり、SARIF と要約のファイルも書かない
- 1 行が上限を超えると、それより後の行は要約に入らない。ログと SARIF には全てが残る
