# 0026. エージェントのジョブが `needs:` で待つ前のジョブの `if:` も、エージェントのステップの条件として読む

- ステータス: 承認
- 日付: 2026-11-14

## 文脈

- ADR 0012 は、エージェントのジョブとステップの `if:` だけを読み、`needs:` で待つ前のジョブの `if:` は見ないとした。トレードオフに、前のジョブ(dispatch のジョブ)で絞る形は誤検知になると書いた
- ADR 0021 の調査で、判断できなかった 4 件のうち 1 件と、`error` の確かめで残った誤検知の 1 件が、この形だった
- 本人に次に直す誤検知の形を聞き、2026-11-14 にこの形が選ばれた
- GitHub の文書(2026-11-14 に確かめた)
  - workflow syntax の `jobs.<job_id>.needs`: 前のジョブが失敗するか skip されると、それを待つジョブは、続ける条件式を使わない限り skip される。依存の連鎖では、失敗や skip はそこから先の全てのジョブに及ぶ
  - expressions の status check functions: `if:` に状態の関数が無ければ、既定で `success()` が付く。前のジョブが成功しなくても動かすには `always()` を使う。`failure()` は前のジョブのどれかが失敗すると真になる。前のジョブが skip されたときの `failure()` と `cancelled()` の値は書かれていない

## 検討した選択肢

1. エージェントのジョブの `if:` に `always()`、`failure()`、`cancelled()` が無ければ、`needs:` の前のジョブの `if:` も条件として加える。前のジョブについても同じ規則で、さらに前のジョブへたどる
2. 状態の関数に関わらず、前のジョブの `if:` を全て加える
3. 1 に加えて、前のジョブの `run` が権限を確かめて失敗する形(`gh api` で起動した人の権限を見て `exit 1` など)も読む
4. これまでどおり、前のジョブは見ない

## 決定

高橋さんが判断を任せ(2026-11-14 に、次に直す誤検知の形としてこれを選び、進め方は「承認を求めないでどんどん続けていい」)、Claude が 1 を選んだ。

- エージェントのステップの条件は、ステップの `if:`、ジョブの `if:`、`needs:` でたどれる前のジョブの `if:` の全てを「かつ」でつないだものとする
- 前のジョブへたどるのは、待つ側のジョブの `if:` に `always()`、`failure()`、`cancelled()` が無いときだけ。`success()` は既定と同じなので、たどる妨げにしない
- 前のジョブが再利用できるワークフローを呼ぶジョブ(`uses:`)でも、その `if:` を読む
- 同じジョブを二度たどらない
- 加えた条件は、起動した人の比較(ADR 0012)、ラベル(ADR 0023)、上流の判定(ADR 0022、0024)、`if: false` で動かない判定の全てに、ジョブの `if:` と同じく効かせる

## 理由

- 状態の関数が無いジョブは、前のジョブが skip されれば必ず skip される。前のジョブの `if:` が偽なら、エージェントは動かない。文書のとおりの振る舞いなので、条件を「かつ」でつなぐのは正しい
- `always()` があると前のジョブが skip されても動くので、加えると見逃しになる(選択肢 2)。`failure()` と `cancelled()` は skip のときの値が文書に無いので、分からないものは数える側に倒す
- `run` の中の権限の確かめは書き方が多く、ADR 0025 の検討で、列挙では閉じないことが分かっている(選択肢 3)
- ADR 0012 で既知の制限として残した誤検知で、調査にも現れている(選択肢 4)

## 受け入れたトレードオフ

- 前のジョブの `run` で権限を確かめて失敗させる形、出力に結果を書いてエージェントのジョブの `if:` で比べる形(`needs.<id>.outputs.<name> == 'true'`)は、これまでどおり絞っていないものとして扱う(誤検知が残る)
- `if: ${{ !cancelled() && ... }}` のように、前のジョブの結果を問わない書き方のジョブは、前のジョブで絞っていても数える
- 前のジョブの `if:` が skip ではなく、そのジョブのステップの失敗で止める形は読まない

## 再検討する条件

- 調査で、前のジョブの出力で絞る形の誤検知が多いと分かったとき
- GitHub の文書に、skip されたときの `failure()` と `cancelled()` の値が書かれたとき
