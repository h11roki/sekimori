# 0050. オプションで任意のコマンドを動かせる道具は、前方一致で許すと広い道具とする

- ステータス: 承認
- 日付: 2026-11-19

## 文脈

- ADR 0013 と 0041 は、シェルと任意のコードを動かす道具(インタプリタ、`env` や `xargs` のような包み、パッケージを取って動かすコマンド、引数ごとの `git`)を前方一致で許すことを広い道具とした。`find` や `sed` のような読むための道具は、範囲を絞った許可とみなしてきた
- 2026-11-19 の正誤の確かめ(ADR 0049)で、判定者が `Bash(find:*)` を規則の外の危険として挙げた。`find . -exec sh -c '...' \;` で任意のコマンドを動かせる
- 同じく、オプション 1 つで任意のコマンドを動かせる、よく許される道具がある
  - `find`: `-exec`、`-execdir`、`-ok`、`-okdir`
  - `fd`: `-x`、`--exec`、`-X`、`--exec-batch`
  - `rg`(ripgrep): `--pre` で、読む前に任意のコマンドを通す
  - `sed`(GNU): `e` コマンドと `s///e` の `e` フラグで、行をシェルのコマンドとして動かす(ubuntu のランナーの `sed` は GNU)
  - `tar`(GNU): `--to-command`、`--checkpoint-action=exec=`、`-I` と `--use-compress-program`
  - `sort`(GNU): `--compress-program`、`split`(GNU): `--filter`
  - `git grep`: `-O` と `--open-files-in-pager` で、ページャーとして任意のコマンドを動かす
  - `rsync`: `-e` と `--rsh` で、つなぐためのシェルとして任意のコマンドを動かす
  - `git fetch`、`pull`、`clone`、`ls-remote` の `--upload-pack`、`git push` の `--receive-pack`、`git difftool` の `-x` と `--extcmd`、`git archive` の `--exec`
  - `zip` の `-TT`、`ssh` の `-o ProxyCommand=`
- Claude Code と Gemini CLI の前方一致の許可は、許した前置きの後ろに何を続けても通す。オプションは前置きの後ろのどこに置いてもよいので、`Bash(find . -name:*)` のように前置きを長くしても、`-exec` を後ろに足せる
- 公開ワークフロー 2,044 件では、Claude の `Bash(...)` か Gemini の `run_shell_command(...)` でこれらを許すファイルが、`find` で 29、`sed` で 12、`rg` で 6、`tar` で 2 あった(重なりを含む)

## 検討した選択肢

1. これらの道具は、前方一致で許せば前置きの長さに関わらず広い道具とする。完全一致の許可は今のとおり絞った許可とする
2. 前置きに `-exec` などのオプションそのものが含まれるときだけ広い道具とする
3. 今のまま、絞った許可とみなす

## 決定

高橋さんが判断を任せ(2026-11-19 に「改善すすめて」)、Claude が 1 を選んだ。

- `find`、`fd`、`rg`、`sed`、`tar`、`sort`、`split`、`rsync`、`zip`、`ssh` と、`git` の `grep`、`fetch`、`pull`、`clone`、`ls-remote`、`push`、`difftool`、`archive` を前方一致で許す規則(`Bash(find:*)`、`Bash(sed -n:*)`、`Bash(git grep:*)`、Gemini の `run_shell_command(find)` など)は、それだけで広い道具とする。書き換えの有無は問わない
  - インタプリタの一覧(ADR 0013)にも、`awk` の別の実装の `gawk`、`mawk`、`nawk` を足す
  - 別の名前で入る同じ道具も含める。Ubuntu の apt で入れた `fd` の `fdfind`、Homebrew の GNU の道具の `gfind`、`gsed`、`gtar`、`gsort`、`gsplit`、BSD の `bsdtar`
- Claude の規則で `*` が途中にあるもの(`Bash(find * -print)`)は、最初の `*` までを前置きとする。`*` は何にでも当たるので、その後ろの文字は前置きの後ろに続けられるものを絞らない。この読み方は、この ADR の道具に限らず、全ての `Bash(...)` の許可に使う。拒否の規則は、途中の `*` を前置きの終わりとしては読まない。`Bash(find * -exec*)` のような拒否は `find` の一部だけを拒むので、`find` 全体を拒んだとみなすと見逃しになる
- 下位コマンドは、`-C` や `-c` のような値を取る全体のオプションとその値を飛ばして探す。ADR 0043 の書き換えと同じ関数で読み、パッケージを動かす下位コマンド(ADR 0041 の `npm exec`、`git rebase` など)もこの読み方にそろえる
- `sed`、`rsync`、`git pull`、`git clone` は、前方一致で許せば広い道具になるので、ADR 0043 の書き換えのコマンドの一覧からは外す。完全一致の規則は書き換えとして読まないので、結果は変わらない
- 広い道具は任意のコマンドを動かせるので、ファイルの書き換えもできるとみなす(ADR 0043 の書き換えと同じ)。`agent-code-with-secrets` のような書き換えに頼る規則にも効く
- 完全一致の規則(`Bash(find . -name src)`)は、後ろに足せないので数えない。`*` を含む規則は、どこに `*` があっても前方一致として読む
- `sed` は ADR 0043 で書き換えのコマンドとしても数えている。広い道具になっても、書き換えの理由の書き方は変えない

## 理由

- 前方一致の許可は、オプションを後ろに足すことを止められない。2 は `Bash(find:*)` の後ろに `-exec` を足す形を見逃す
- `git` を引数ごと許すと `-c alias.x='!cmd'` で任意のコマンドを動かせるとして広い道具にした(ADR 0043)のと同じ扱いになる

## 受け入れたトレードオフ

- `sed` は macOS の BSD の `sed` では `e` コマンドが無いが、ランナーの多くは Linux なので区別しない
- 一覧はよく許される道具だけで、全てではない。`less`、`vim`、`awk` 以外の言語処理系の多くは載せていない(`awk` はインタプリタとして ADR 0013 で数えている)
- `grep` はコマンドを動かすオプションを持たないので数えない
- 完全一致の規則が `find -exec` や `fd -x` でリポジトリのスクリプトを動かす形と、エージェントの後の `run` のステップがこの形でスクリプトを動かす形は、プロジェクトのコードを動かすとは読まない
- `gh alias set --shell` のように、まれにしか許されない道具は載せていない
- `Bash(fin*)` のように語の途中の `*` は、その語を名前として読むので、`find` などに当たることを見落とす
- 引用符の中に空白を含む値(`git -C "my repo" grep`)は、空白で区切って読むので下位コマンドを見落とすことがある
- 指摘の文は、他の広い道具と同じく許可の規則を示すだけで、どのオプションで任意のコマンドを動かせるかは書かない。README と規則の説明に書く
