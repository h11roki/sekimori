# 0023. 付けたラベルの名前で絞った `if:` は、起動した人を絞ったものとして扱う

- ステータス: 承認
- 日付: 2026-11-13

## 文脈

- ADR 0021 の調査で、`error` の指摘から無作為に選んだ 15 件を確かめると、8 件が誤検知だった。全て run-gemini-cli の、起動できる人の軸の誤りだった
- 最も多い原因(3 件)は、ラベルで絞る次の形だった
  - `on: issues: types: [labeled]` と `if: github.event.label.name == 'agent:gemini'`
  - `if: contains(github.event.issue.labels.*.name, 'honeypot')`
- GitHub の文書(2026-11-13 に確かめた)
  - 組織のリポジトリの役割の表で、「Apply/dismiss labels」は Read に無く、Triage 以上にある
  - 個人のリポジトリでは、ラベルの管理は共同作業者のもの
  - issue のテンプレートとフォームの `labels` は、そのテンプレートで作られた issue に自動で付く。開いた人の権限による制限は書かれていない
- `github.event.label.name` は、`labeled` の操作で付けたラベルを表す。その実行を起こしたのは、ラベルを付けた人になる
- `github.event.issue.labels.*.name` などは、issue や PR に今付いているラベルの一覧を表す。一度付いたラベルは残るので、後から外部の人がコメントしたり、本文を編集したり、PR に commit を足したりした実行でも、一覧の確かめは通る
- ラベルで絞っても、絞るのは起動できる人だけで、issue の本文は外部の人が書いたままエージェントに届く。ADR 0007 の 0.5(外部の人の文面が届く)の形と同じ

## 検討した選択肢

1. 付けたラベルの名前(`github.event.label.name`)を定数と比べる形だけを、起動した人の比較と同じく、絞っているものとして扱う(起動できる人の軸は 0.5)
2. 1 に加えて、今付いているラベルの一覧に含まれるかを確かめる形も、絞っているものとして扱う
3. ラベルで絞る形を、起動できる人の軸から外す(0)
4. これまでどおり、絞っていないものとして扱う

## 決定

高橋さんが判断を任せ(2026-11-13 に「どんどんやっていいよ。承認求めずに」)、Claude が 1 を選んだ。

- `github.event.label.name == '<名前>'`(左右はどちらでもよい)を、ADR 0012 の起動した人の比較と同じく、その経路を絞るものとして読む
- 比べるのは定数だけ。`!=` のように、ラベルが付いていないことを求める形は絞らない
- 今付いているラベルの一覧(`contains(github.event.issue.labels.*.name, ...)` など)は読まない
- どのイベントにも効かせる。ペイロードに `label` が無いイベントでは、比較は偽になり、そもそも動かないため。workflow_run のペイロードにも `label` は無いので、ADR 0022 の上流の判定では、この比較のある経路を動かない経路として除く
- 起動できる人の軸は 0.5 として残す

## 理由

- ラベルを付けるには triage 以上の権限が要るので、外部の人は自分で起動できない。メンテナーが中身を読んでから付ける運用で、claude-code-action が既定で書き込める人に絞るのと同じ守りになる
- 今付いているラベルの一覧は、ラベルを付けた後の外部の人のコメントや編集でも通るので、起動した人を絞らない(選択肢 2)
- 本文は外部の人が書いたものなので、0 にすると、ラベルを付けた後に届く指示の注入を見落とす(選択肢 3)
- 調査の `error` の誤検知の最も多い原因で、残すと誤りのままになる(選択肢 4)

## 受け入れたトレードオフ

- issue のテンプレートがそのラベルを自動で付けるなら、外部の人がテンプレートから issue を開くだけで起動できる。テンプレートはワークフローの外にあるので、sekimori は読まない
- ラベルを付ける triage の役割の人は、書き込み権限を持たないことがある。sekimori は、triage の人を外部の人として扱わない
- ラベルの名前を `contains(github.event.label.name, ...)` のような部分一致で確かめる形は読まない
- 今付いているラベルの一覧で絞り、トリガーを `types: [labeled]` などラベルを付ける操作だけにしているワークフローは、実際には付けた人に絞られているが、絞っていないものとして扱う。調査の誤検知のうち 1 件(`types: [opened, labeled]` と一覧の確かめ)は、テンプレートが付けない限りこれに近い形だった
- `issue_comment` のように `label` の無いイベントでは、比較のある経路は動かないが、そのイベントは外部の人の文面が届くイベント(0.5)として残る

## 再検討する条件

- テンプレートが付けるラベルで起動される事件や報告が出たとき
- `.github/ISSUE_TEMPLATE` も読む作りにするとき
